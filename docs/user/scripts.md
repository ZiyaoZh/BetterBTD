# 脚本与脚本库

BetterBTD 使用托管脚本库保存脚本文件、显示信息和自动任务绑定。日常导入、编辑、运行和导出都应从“我的脚本”页面开始。

## 核心概念

| 概念 | 说明 |
| --- | --- |
| 托管脚本库 | BetterBTD 在安装目录 `User\MyScripts\` 中维护的脚本仓库 |
| 脚本 ID | 每个托管脚本的唯一标识，自动任务通过它定位脚本 |
| 脚本元数据 | 地图、难度、模式、英雄、说明和标签 |
| 任务绑定 | 自动任务槽位与脚本 ID 之间的映射 |

标签用于筛选和说明，不能代替自动任务绑定。

## 支持的文件

- `.btd`：当前推荐格式
- `.json`：符合当前 BetterBTD 脚本结构的 JSON 文件
- `.btd6`：旧版单脚本，可导入转换
- `.btd6s`：旧版脚本包，可批量导入转换

旧格式转换后应逐个检查元数据、对象引用和坐标。转换表示“尽力迁移”，不保证与旧执行器完全一致。

## 管理脚本

“我的脚本”页支持：

- 导入、导出和删除脚本
- 复制脚本 ID
- 按关键字、地图、难度和模式筛选
- 查看说明、英雄、标签和文件状态
- 打开编辑器或直接运行

脚本可能显示为以下状态：

- **就绪**：文件和元数据有效，可以编辑、运行和绑定。
- **文件缺失**：索引仍在，但脚本资产已被移动或删除。
- **元数据异常**：文件存在，但关键字段无法按当前格式解析。

异常脚本不应继续用于自动任务。优先重新导入或在编辑器中修复。

## 推荐的整理方式

- 名称写清地图、打法或用途。
- 说明记录开局前提、英雄皮肤、知识点或已知风险。
- 地图、难度、模式和英雄必须与实际脚本一致。
- 标签用于活动、路线或作者自定义分类。
- 分享自动任务整套配置时使用订阅包，避免只传脚本而丢失绑定。

## 使用脚本编辑器

典型流程：

1. 新建脚本，或从脚本库打开已有脚本。
2. 填写地图、难度、模式、英雄、说明和标签。
3. 从指令库添加指令并排列顺序。
4. 设置目标对象、升级路径、坐标、等待条件和操作间隔。
5. 保存为 `.btd`。
6. 运行当前工作区，查看每一步状态和日志。
7. 修正后再次保存；从脚本库打开的文件会同步更新库记录。

## 常用指令

| 类别 | 指令示例 |
| --- | --- |
| 放置与管理 | 放置防御塔或英雄、升级、卖出、切换目标、修改坐标 |
| 技能与物品 | 设置塔能力、使用英雄物品、触发技能栏技能 |
| 流程控制 | 等待时间、金钱、回合或颜色，发送下一轮，切换快进 |
| 通用操作 | 鼠标点击、注释 |

注释不会操作游戏，只用于说明脚本意图。

## 坐标与颜色取点

需要坐标时，不建议手工输入：

1. 启动截图器。
2. 在编辑器中选择目标指令。
3. 点击“选择坐标”。
4. 将鼠标移动到游戏窗口目标位置。
5. 右键确认。

程序会显示参考坐标、窗口坐标和当前像素颜色。颜色信息可用于“等待颜色”指令。

脚本坐标按 `1920 × 1080` 保存。编写和运行脚本时都保持相同的 16:9 布局最稳定。

## 对象引用

脚本会为每次放置生成稳定对象引用，后续升级、卖出和切换目标都通过该引用找到对应防御塔。

- 放置顺序会影响对象列表和默认编号。
- 删除、复制或移动放置指令后，应重新检查后续目标。
- 多只同类防御塔不能只靠类型区分，坐标和对象绑定同样重要。

## 高级参数

放置检测、失败微调、升级检测、面板检测、点击间隔和指令间隔等高级参数已有默认值。只有在主流程正确、个别步骤仍不稳定时再调整，并且每次只改一个变量。

## 运行与排错

你可以从“我的脚本”运行已保存脚本，也可以从编辑器运行当前工作区。运行窗口会显示：

- 指令序列与当前步骤
- 每一步的状态
- 运行日志和日志文件路径
- 当前间隔策略
- 开始、停止以及 F10 热键状态

建议分段编写和验证：先完成开局放塔，再补升级和等待，最后加入卖出、技能与回合控制。出现问题时，先定位第一条失败指令，不要同时修改整个脚本。

## 导入与分享

- 分享单个脚本：从脚本库导出 `.btd`。
- 分享整套自动任务：使用对应任务的订阅导出功能。
- 迁移本机数据：备份整个 `User\MyScripts\`，并同时备份应用配置。

脚本文件格式的开发者规范见 [脚本文件格式](../developer/script-file-format.md)。
